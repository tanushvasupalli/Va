## 2024-05-24 - Database Connection Pooling with psycopg2
**Learning:** `psycopg2` standard connection pools (`ThreadedConnectionPool`) lack built-in pre-ping (liveness checks) and retry queues. Supabase (and other cloud providers) may drop idle connections aggressively. Furthermore, using `autocommit=True` conflicts with `psycopg2`'s native connection `__enter__` block.
**Action:** When implementing database pooling in psycopg2, always use a proxy class to safely manage the `__exit__` pool return and pre-ping the connection (`conn.closed`) before yielding it to the caller. Ensure the proxy supports usage outside context managers. Additionally, gracefully fall back to direct connections if the pool fails to initialize (e.g. in test environments with invalid credentials).
