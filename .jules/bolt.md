## 2024-05-15 - Optimizing Database Latency and Testing Constraints
**Learning:** Initializing connections directly (e.g., `psycopg2.connect`) for every database query introduces significant latency overhead from constant TCP/TLS handshakes, especially for cloud storage like Supabase. Furthermore, direct connection at the module or class initialization level can cause immediate `OperationalError` exceptions in testing sandboxes where `SUPABASE_DATABASE_URL` credentials are bad or missing, breaking test collection altogether.
**Action:** Use connection pooling (like `psycopg2.pool.ThreadedConnectionPool`) to reuse connections. Always wrap pool initialization in a try/except block to catch `psycopg2.OperationalError` gracefully, ensuring the application and test collection don't crash when DB variables are unavailable in test environments. Yield connections from the pool via a context manager to prevent connection leaks.
