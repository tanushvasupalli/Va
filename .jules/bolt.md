## 2024-05-24 - Database Connection Pooling Optimization
**Learning:** Instantiating a new `psycopg2` connection on every request causes significant TLS/TCP handshake latency overhead, especially with cloud databases like Supabase. Native `psycopg2` context managers conflict with `autocommit=True`, and `ThreadedConnectionPool` lacks built-in pre-ping or retry logic, which can lead to failed connections on cloud databases.
**Action:** Implemented `psycopg2.pool.ThreadedConnectionPool` lazily as an instance variable. Created `PooledConnectionProxy` to safely manage connection context, ensure `autocommit` behavior without transaction conflicts, and return connections to the pool in `close()`. Added pre-ping and retry loop logic to `_get_connection` to prune dead connections and handle pool exhaustion gracefully.
