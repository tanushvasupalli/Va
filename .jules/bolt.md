## 2025-02-23 - Implement Database Connection Pooling
**Learning:** Establishing a new database connection for every query creates significant latency overhead due to constant TCP/TLS handshakes, especially with cloud databases like Supabase. Standard `psycopg2.pool.ThreadedConnectionPool` lacks automatic liveness checks and graceful blocking for new connections. Also, proxying the connection is necessary to prevent `autocommit=True` from conflicting with psycopg2 context managers (`with conn:`).
**Action:** Implement `ThreadedConnectionPool` with a lazy-initialized proxy class that checks `conn.closed` (pre-ping), retries failed connections, and explicitly handles context managers (`__enter__`/`__exit__`) to ensure dead connections are discarded and transactions are handled safely.
