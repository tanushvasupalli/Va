## 2024-05-18 - Optimizing Supabase Connection Handling with Connection Pools
**Learning:** Establishing direct connections to a Supabase Postgres instance continuously can cause significant TCP/TLS handshake latency. However, using `psycopg2.pool.ThreadedConnectionPool` directly in tests with invalid credentials causes fatal runtime errors, and using it in context managers (`with conn:`) breaks auto-commit requirements.
**Action:** When building connection pools for Supabase, always use a `PooledConnectionProxy` wrapper class that instantiates gracefully, implements `close()`, handles custom `__enter__` and `__exit__` methods properly returning connections to the pool, and uses a pre-ping / retry loop to ensure liveness, avoiding standard psycopg2 runtime and context-management conflicts.
