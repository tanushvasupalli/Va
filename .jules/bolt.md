## 2024-10-28 - Connection Pooling with psycopg2
**Learning:** `psycopg2` standard connection pool doesn't have an automatic pre-ping to check if connections are still alive before handing them out. Supabase usually drops idle connections, so fetching from the pool directly will cause `OperationalError` when the connection is dead. Additionally, since the connection objects conflict with `autocommit=True` inside a standard context manager, an advanced proxy class that manually pre-pings the `conn.closed` status is necessary.
**Action:** When adding connection pooling for `psycopg2` in cloud databases (especially Supabase), implement a custom `ConnectionProxy` that verifies connection liveness upon initialization (`conn.closed == 0`), yields it, and manually returns it to the pool (`pool.putconn(conn)`) when done.
