
## 2025-02-23 - Database Connection Pooling and Context Managers
**Learning:** Initializing new database connections per operation using `psycopg2.connect()` creates substantial latency (TCP handshakes, auth) which can be a huge bottleneck for AI agents interacting heavily with cloud databases like Supabase. However, wrapping standard `psycopg2` objects from a `ThreadedConnectionPool` using the native connection context manager throws errors when `autocommit=True` is enabled since it attempts to manage transactions. Additionally, pooling solutions require a pre-ping (checking `conn.closed`) and retry loops to gracefully handle idle timeouts from remote databases and transient `PoolError`s during exhaustion.
**Action:** Always utilize a custom connection proxy wrapper that initializes the connection explicitly, overrides `__exit__` to cleanly return it to the pool via `putconn`, and delegates methods using `__getattr__`. When dealing with serverless or cloud databases, implement pre-ping checks and retries within the connection getter to avoid returning stale connections.
